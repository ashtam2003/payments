What Is Valor PayTech?
Valor PayTech — connecting merchants, banks, and payment networks

Valor PayTech is a full-service payment technology company that provides merchants with everything needed to accept, process, and manage payments — both in-person and online. It acts as a combined payment gateway + merchant portal + device management platform.

🏦 What Valor Does

  • Processes credit, debit, and ACH payments
  • Provides a web portal for merchants (VPOnline)
  • Manages POS devices & virtual terminals
  • Offers tokenization / card vaulting (The Vault)
  • Handles recurring & subscription billing
  • Provides fraud protection (Valor Shield RT)

👥 Who Uses Valor

  • ISO — Independent Sales Organizations (resellers)
  • Sub-ISO — Subsidiary ISOs under a parent ISO
  • Merchants — Businesses that accept payments
  • Operators — Staff at merchant locations
  • Developers — Via API integration
Portal URL

Main merchant portal: https://vponline.valorpaytech.com — This is where all management happens: transactions, vault, reports, settings, virtual terminal, and more.

Webhooks
Webhooks & Callbacks

Webhooks allow Valor to send real-time HTTP POST notifications to your server when events happen — a transaction completes, a recurring payment fails, a chargeback is filed, etc.

🔔 Events That Trigger Webhooks

  • Transaction approved / declined
  • Recurring payment processed or failed
  • Batch settled
  • Chargeback received
  • Vault customer added / deleted
  • ACH return received

⚙️ Webhook Configuration

  • Configure webhook URL in Settings
  • Valor sends HTTP POST with JSON payload
  • Your server must respond with HTTP 200
  • Validate payload using your signature key
  • Log all incoming webhooks for audit trail
Webhook Best Practice

Always respond to webhooks immediately with HTTP 200 before doing any processing. If your server takes too long, Valor may retry the webhook. Process the event asynchronously in a queue to avoid timeouts.

The Vault & Tokenization
The Vault
The Vault — Overview & Benefits
The Vault — encrypts and tokenizes every card the first time it's used

The Vault powered by Valor is a premium feature that lets merchants securely store and retrieve customer card details — enabling quick transactions without re-entering card information. Cards are encrypted and replaced with unique tokens following PCI DSS standards.

🔐
Tokenization

Real card numbers are replaced with a unique token (e.g., VLT_TOKEN_XXXX). The merchant never stores or sees the raw card number after the initial entry.

📋
Up to 5 Cards Per Customer

Each Vault customer can have up to 5 saved cards and 5 address records. Cards can be deleted or added at any time.

🚫
CVV Not Required for Vault Charges

Once a card is tokenized, CVV is not required to process future charges. The token carries the card's validity.

🔁
Recurring Billing Support

Vault tokens can be used for automated recurring billing — weekly, monthly, or custom schedules.

📊
Audit Log

Every change to a customer's Vault record is logged — who changed it, when, from what IP, and what changed.

🔓 Enabling The Vault

The Vault is a premium module. ISO or Sub-ISO must enable it for merchants during onboarding. To check: look for "Vault" in the left sidebar of VPOnline. If not visible, contact your ISO to enable it. Merchants must then enable it for their operators.

Fraud & Security
Fraud Tools
Valor Shield RT & Fraud Protection
Valor Shield RT — real-time fraud detection on every transaction

Valor Shield RT is Valor's real-time fraud detection module. It evaluates every transaction against configurable rules before forwarding for bank authorization. Suspicious transactions can be auto-declined, held for review, or flagged.

→
AVS — Address Verification System
CodeAddress Match?ZIP Match?Meaning & Action
Y✅ Yes✅ YesFull match — lowest fraud risk. Proceed normally.
A✅ Yes❌ NoStreet matches but ZIP doesn't. Review or proceed with caution.
Z❌ No✅ YesZIP matches but street doesn't. Review.
N❌ No❌ NoNeither matches — high fraud risk. Strongly consider declining.
U——Unavailable — issuer doesn't support AVS. Common with international cards.

Common Fraud Risk Flags
🚨 Velocity Triggers

Too many transactions from same card or IP in short time — card testing pattern

💰 Unusually Large Amount

Transaction far exceeds merchant's typical average — processor may hold account

🌍 Geographic Mismatch

Card BIN country doesn't match billing address or IP location

⚠️ AVS + CVV Both Fail

Both address and CVV mismatch simultaneously — very high risk signal

🔢 Multiple Declines Same Card

Same card declined multiple times — potential stolen card being tested

📱 Card Testing Pattern

Small amounts ($0.01, $1.00) followed by larger charges — confirms card works

Security
PCI DSS & Encryption

🛡️ PCI DSS Compliance

Payment Card Industry Data Security Standard. Valor is PCI DSS compliant — all card data is handled according to these mandatory industry security rules.

  • Card numbers encrypted at rest and in transit
  • CVV never stored after authorization
  • Tokenization eliminates PAN storage risk
  • Regular security audits performed

🔒 How Encryption Works

  • SSL/TLS: All data transmitted over HTTPS encrypted connections
  • Tokenization: Raw PAN replaced with token at first use
  • Point-to-Point Encryption (P2PE): Card encrypted at hardware device level
  • Valor never stores raw CVV — ever
  • Merchants using Vault are significantly reducing their PCI scope
✅ Merchant PCI Benefit

By using The Vault and Virtual Terminal, merchants significantly reduce their PCI DSS compliance burden. Raw card data flows through Valor's PCI-compliant infrastructure — merchants never store or handle card numbers themselves.

ACH & Recurring Billing
ACH
ACH / eCheck Payments in Valor

📋 What ACH Requires

  • Bank Routing Number (9-digit ABA number)
  • Account Number (checking or savings)
  • Account Type (Checking / Savings)
  • Account Holder Name

✅ Why Use ACH in Valor

  • Much lower fees (~$0.25–$1.50 flat vs 2–3% card)
  • Available in Virtual Terminal → ACH tab
  • Supports recurring ACH billing
  • Ideal for B2B, large invoices, subscriptions

ACH Return Timing

Unlike card declines (instant), ACH return codes arrive 1–3 business days after the transaction. Design your system to handle delayed failures and notify customers when ACH returns occur.

💡 Reconciliation Formula

Bank Deposit = Batch Total − Interchange Fees − Network Fees − Processor Fees. Typical deduction: 2–3% of batch total. Use the batch detail in Valor Reports to verify the expected deposit, then match to your bank statement.

2
Duplicate Transaction Error

⚠️ What Happens

Valor (and most processors) detect duplicate transactions — same card, same amount, within a short time window. The second transaction is rejected with a "Duplicate Transaction" error.

✅ How to Fix

Wait 5–10 minutes before retrying the same card/amount combination. Or add a unique invoice number to each request to differentiate transactions. Check the Transactions module first to confirm the original didn't process before retrying.

⚠️ Common Cause

Network timeout — the first request sent but the response never returned. The transaction DID process. Always check VPOnline before assuming a timeout means a failure and retrying.

3
Vault / Token Issues
TOKEN INVALID
Token Not Found or Expired

Vault customer was deleted, or token was from a different environment (sandbox vs live). Re-add the customer to Vault to get a fresh token.

CARD EXPIRED
Saved Card Has Expired

Even in Vault, the underlying card can expire. Go to Vault → Edit Customer → Add new card with updated expiry. Delete the old expired card.

CVV REQUIRED
CVV Prompted Unexpectedly

This should not happen for Vault transactions. Check that you're using the Vault token path (not manual card entry) in the Virtual Terminal.

VAULT DISABLED
Module Not Enabled

The Vault module was disabled for this merchant or operator. Contact your ISO to re-enable Vault access in the merchant's module settings.

4
Settlement Mismatch

❌ Problem: Deposit doesn't match batch total

  • Fees deducted (interchange, network, gateway) — expected
  • Refunds processed reduced net deposit
  • Void after batch submitted — adjustment in next deposit
  • Timing difference — settlement may post next business day

✅ Resolution Steps

  • Go to Reports → Batch Detail for that day
  • Subtract expected fees from batch total
  • Check if any refunds were issued that day
  • Compare adjusted total to bank deposit
  • If still mismatched, contact Valor support with batch number
5
Sudden Multiple Declines (Account-Level)
🚨 All payments suddenly declining?

If every transaction starts failing at once, the issue is likely account-level, not card-level. Check these in order:

1. Fraud filter triggered?2. Account in review mode?3. Transaction limit reached?4. API credentials wrong environment?5. Processor system outage?
Action: Contact Valor Support

If you've checked the above and can't identify the cause, contact Valor PayTech support at 1.800.615.8755 or email sales@valorpaytech.com. Have your EPI number and a sample declined transaction reference number ready.

Quick Reference — Error Checklist

📋 Single Card Declined

  • Check response code (05, 51, 54, 14?)
  • Verify card number, expiry, CVV entered correctly
  • Check billing address matches bank records (AVS)
  • Ask customer to call their bank
  • Try a different payment method

📋 All Payments Declining

  • Check VPOnline dashboard for alerts
  • Verify API credentials (right environment?)
  • Check transaction limits in Settings
  • Look for fraud filter triggers (Shield RT)
  • Call Valor support: 1.800.615.8755

📋 ACH Return / NSF

  • Wait for return code (R01, R02, etc.)
  • Notify customer of failed ACH immediately
  • Request updated bank info if R02/R03/R04
  • Do not auto-retry without customer authorization

📋 Vault / Token Error

  • Confirm Vault module is enabled for user
  • Verify customer still exists in List Customer
  • Check if saved card has expired
  • Re-add customer if token invalid
  • Ensure using Virtual Terminal (not POS) for Vault charges
